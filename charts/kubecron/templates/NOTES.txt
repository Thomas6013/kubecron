KubeCron has been deployed in SERVER (collector) mode.

  It serves no dashboard. It records CronJob runs — outcomes, exit codes,
  15-second CPU/memory samples and the log body of each run — and answers the
  read-only API a console reads:

    GET /api/v1/collector    what this collector holds and can answer
    GET /api/v1/clusters
    GET /api/v1/clusters/{cluster}/cronjobs
    GET /api/v1/clusters/{cluster}/cronjobs/{ns}/{name}/runs
    GET /api/v1/runs/{id}/logs

  It records from now on. There is no backfill: runs that happened before this
  install were never observed by anything, and the API reports the moment it
  started watching so a console can draw that period as unwatched rather than
  as an absence of runs.

  ⚠️  NO API TOKEN (api.token is empty)

  reach this Service can read your whole CronJob inventory, every run outcome
  and every captured log body.
